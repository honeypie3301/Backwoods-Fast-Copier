# Code-Based Procedural Generation in MCreator (NeoForge 1.21.1 & 26.1.2)

## Architectural Guide & Optimization Fixes

This guide documents the worldgen architecture, multi-chunk bounds safety, and performance optimization techniques for custom Java feature classes (`Feature<NoneFeatureConfiguration>`).

---

### 1. Eliminating "Detected setBlock in a far chunk" Errors in NeoForge 26.1.2

#### The Problem:
In NeoForge 26.1.2, `WorldGenRegion` strictly enforces chunk write boundaries. If a feature running in chunk `(chunkX, chunkZ)` attempts to set a block outside `[chunkMinX, chunkMinX + 15]` or `[chunkMinZ, chunkMinZ + 15]` (or its immediate 1-chunk region), Minecraft logs:
`Detected setBlock in a far chunk [X, Z], pos: MutableBlockPos...` and discards the block write.

#### The Solution (Intact Chunk Footprint Containment):
Calculate the building footprint bounds (minX, maxX, minZ, maxZ) so they are **100% contained within the local chunk**:

```java
int chunkMinX = origin.getX() & ~15;
int chunkMinZ = origin.getZ() & ~15;

// Building footprint: 5x5 to 10x10
int widthX = 5 + random.nextInt(6); // 5 to 10
int widthZ = 5 + random.nextInt(6); // 5 to 10

// Guaranteed: minX >= chunkMinX and maxX <= chunkMinX + 15
int minX = chunkMinX + random.nextInt(Math.max(1, 16 - widthX));
int maxX = minX + widthX - 1;

int minZ = chunkMinZ + random.nextInt(Math.max(1, 16 - widthZ));
int maxZ = minZ + widthZ - 1;
```

### 2. Eliminating Inter-Chunk Gaps (Edge-Anchored Overlapping)

When placing buildings randomly inside `[chunkMinX, chunkMinX + 15 - widthX]`, random offsets can leave 1 to 4 empty blocks on the chunk boundaries. When adjacent chunks both leave boundary blocks empty, a vertical gap/alley forms at chunk borders.

#### The Edge-Anchoring Fix:
In each chunk, explicitly anchor buildings to the 4 chunk edges before placing interior buildings:

```java
// 1. Min X edge tower
minX = chunkMinX;
maxX = minX + widthX - 1;

// 2. Max X edge tower
maxX = chunkMinX + 15;
minX = maxX - widthX + 1;

// 3. Min Z edge tower
minZ = chunkMinZ;
maxZ = minZ + widthZ - 1;

// 4. Max Z edge tower
maxZ = chunkMinZ + 15;
minZ = maxZ - widthZ + 1;
```

This guarantees $100\%$ gapless, seamless coverage across chunk borders with zero vertical alleys.

### 3. Performance Optimization Techniques

1. **Pre-Cached Static `BlockState` Constants**:
   ```java
   private static final BlockState PLANKS = Blocks.OAK_PLANKS.defaultBlockState();
   private static final BlockState AIR = Blocks.AIR.defaultBlockState();
   ```
   Avoids allocating new `BlockState` objects per block in generation loops.

2. **`BlockPos.MutableBlockPos` for Zero GC Pressure**:
   ```java
   BlockPos.MutableBlockPos mutablePos = new BlockPos.MutableBlockPos();
   mutablePos.set(x, y, z);
   level.setBlock(mutablePos, PLANKS, 2);
   ```
   Prevents GC spikes during deep foundation scans.

3. **Flag 2 `setBlock` (No Block Updates or Physics Cascades)**:
   Always use `level.setBlock(pos, state, 2)` (Flag 2 = `Block.UPDATE_CLIENTS`).

### 5. Self-Writing DataPack JSON Literal Escaping (`:compileJava` Fix)

#### The Problem:
When feature classes automatically generate configured feature, placed feature, or biome modifier JSONs into development workspace resources (`autoGenerateDataPackJsons()`), string literals representing JSON structures must escape internal quotation marks with backslashes (`\"`). If quotes are emitted raw without backslash escaping (e.g., `"{"type":"" + ID + ""}"`), the Java compiler treats them as prematurely closed string literals, throwing multiple syntax errors:
```text
error: ')' or ',' expected
error: ';' expected
error: not a statement
```

#### The Solution:
Always escape all double quotes within internal JSON payloads:
```java
outputs.put("data/the_backwoods/worldgen/configured_feature/crossworks_lattice.json",
    "{\"type\":\"" + ID + "\",\"config\":{}}");
outputs.put("data/the_backwoods/worldgen/placed_feature/crossworks_lattice_placed.json",
    "{\"feature\":\"" + ID + "\",\"placement\":[{\"type\":\"minecraft:biome\"}]}");
outputs.put("data/the_backwoods/neoforge/biome_modifier/add_crossworks_lattice.json",
    "{\"type\":\"neoforge:add_features\",\"biomes\":\"" + BIOME_ID + "\",\"features\":\"the_backwoods:crossworks_lattice_placed\",\"step\":\"surface_structures\"}");
```

### 6. Vertical Stacking & Collision Avoidance

When multiple custom features populate the same dimension ceiling:
- **Lattice Base Height**: `gridTopY = max - Math.max(ELEVATION_OFFSET_FROM_TOP, totalRoofHeightNeeded)`, `gridBaseY = gridTopY - VERTICAL_THICKNESS`. For `ROOF_PLATE_2_HEIGHT_OFFSET = 35` and `VERTICAL_THICKNESS = 30`, `gridBaseY = max - 71`.
- **Ward Clearance Setting**: Set `SuspendedWardFeature.ROOF_OFFSET_FROM_TOP = 110` (or higher).
- **Collision Avoidance Rule**: To ensure the top of the Suspended Ward is not cut off or colliding with the bottom of the Crossworks Lattice, maintain `SuspendedWardFeature.ROOF_OFFSET_FROM_TOP > totalRoofHeightNeeded + VERTICAL_THICKNESS`. Increasing `ROOF_OFFSET_FROM_TOP` moves the Ward roof lower in Y.

### 7. Bridge Level Alignment & Connected Fence Railings

- **Bridge Deck Alignment**: The bridge deck generates flush with the lattice top layer at `y = gridTopY - 1` with `BRIDGE_THICKNESS = 1`.
- **Bridge Extension**: Bridges extend by `BRIDGE_EXTENSION = 5` blocks into adjacent sector boundaries to overlap with interior beams, eliminating walking gaps.
- **Directional Fence Connectivity**: Fences placed in worldgen require explicit `BlockStateProperties` values to connect horizontally without neighbor updates:
  - X-spanning bridge railings: set `BlockStateProperties.EAST` and `BlockStateProperties.WEST` to `true`.
  - Z-spanning bridge railings: set `BlockStateProperties.NORTH` and `BlockStateProperties.SOUTH` to `true`.
  - Crossing intersections: preserve central walkway blocks as open air and connect outer corner posts multi-directionally.

### 8. Outer Roof Plate 2 & Adaptive Rubber-Band Stairs Architecture

- **Vertical Stacking Clearance**: Set `ELEVATION_OFFSET_FROM_TOP = 20` so `gridTopY = max - 20` and `gridBaseY = max - 50`. Since Suspended Ward tops out at `effectiveMax = max - 60`, the Lattice sits strictly above the Suspended Ward with a 10-block air clearance, avoiding any structural collision.
- **Ceiling Plate Coverage**: The primary oak ceiling plate (`ENABLE_CEILING_PLATE = true`, thickness 2) generates at `gridTopY + CEILING_PLATE_GAP` (`max - 18`), seamlessly spanning across the entire 1000x1000 boundary (`BOUNDARY_CLAMP_SIZE = 1000`) over both sector interiors and chasm gaps.
- **5-Wide Walkways & Cross-Gap Exclusion**: Set `BRIDGE_WIDTH = 5`, providing a 3-block wide open walkway in the center with outer railing borders. Bridges generate exclusively across single chasm channels (`bridgeX` or `bridgeZ`). All bridge deck and railing placement is completely bypassed in cross gap intersections (`scX.inExtendedGap && scZ.inExtendedGap`), preventing floating intersecting bridge artifacts across open chasm junctions.
